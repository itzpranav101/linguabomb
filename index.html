The problem

Everyone uses language every day, but learning one is still frustrating.

Words with no context

Most apps drill isolated words. Real conversations (a hawker stall, an MRT ride) are never practised.

Taught in the wrong language

A Hindi speaker learning Spanish is usually taught in English. Understanding the explanation becomes a second hurdle.

No honest feedback

Chatbots happily invent words and grammar that sound right but are wrong, and learners cannot tell.

A tutor that knows who you are, explains in the language you choose, and only teaches from verified sources.

RAG: Retrieval-Augmented Generation

The most important word in our project. The model does not answer from memory. It answers from documents we control.

  1. 1. QuestionThe learner asks or taps a button, e.g. Practice.
  2. 2. Query buildingWe turn the learner state into a search query: language + level + goal + activity.
  3. 3. RetrieveThe knowledge base is split into chunks and indexed. The most relevant chunks (an exercise, a grammar entry, a role-play script) are fetched.
  4. 4. AugmentOnly those chunks, plus instructions, are given to the language model as its source material.
  5. 5. GenerateThe model writes the reply in a friendly teacher voice, using nothing outside the retrieved text.
  6. 6. GroundIf nothing relevant is found it says so, instead of inventing an answer.

Plain chatbot

Answers from what it memorised. Can sound confident and be wrong. You cannot check where a fact came from.

RAG chatbot (ours)

Answers from our curated, licence-tracked sources. Fixing a mistake means editing one entry, not retraining anything.

Multi-context retrieval our design

One question is never asked alone. Every retrieval is shaped by several layers of context at the same time.

Learner profile

Name, so replies address the person.

Language pair

Explanation language (what you speak) and target language (what you learn).

Level

Beginner, Intermediate or Advanced decides which entries are eligible.

Goal

Travel, school and exams, culture or fun picks the themed phrase set.

Scenario

Hawker centre, MRT, airport, canteen or new friend selects the role-play script.

Conversation memory

Previous answers and weak areas steer the next exercise and the review.

Honest note for the judges: we did not train or fine-tune model weights. The multi-context behaviour comes from context engineering: structured variables injected into every retrieval query. That is faster to build, auditable, and avoids hallucinated vocabulary.

Live sync: ntfy.sh publish / subscribe

How the chatbot talks to this website without a backend server.

Publisher

The chatbot. After each activity it sends one message.

Broker

ntfy.sh, a free pub/sub service that receives and relays messages.

Topic

A long random channel name (like a private radio frequency). Only publishers and subscribers who know it can use it.

Subscriber

This website. Every page keeps a live connection open to the topic.

Workflow, step by step

  1. 1. Learner finishes an activityFor example Grammar in the chat.
  2. 2. Bot publishesA Chatling HTTP Request block POSTs one line to the topic URL: LBSYNC | Spanish | Beginner | Grammar | Pranav | coach note
  3. 3. Broker fans outntfy.sh stores the message briefly and pushes it to every open subscriber (server-sent events, no polling).
  4. 4. Website receivessync.js reads the event stream and ignores anything that is not a message.
  5. 5. De-duplicateEach event has an id. Seen ids are remembered, so a reconnect never double-counts.
  6. 6. InterpretLanguage and level become codes; the activity becomes a letter (L learn, G grammar, P practice, R role-play, Q quiz, X extras) and is added to a running tally.
  7. 7. AwardThe progress engine awards only the new XP, updates the streak and unlocks badges.
  8. 8. ShowThe name chip, XP chip, progress dashboard and AI Coach card refresh live. The header pill shows Live sync: connected.
Chatbot (publisher)        ntfy.sh (broker)           Website (subscriber)
      |  POST /topic  LBSYNC|...  |                            |
      |-------------------------->|  SSE stream (open)         |
      |                           |--------------------------->|
      |                           |      event {id, message}   |  de-dup, parse, award XP
      |                           |<-- auto-reconnect + replay-|  (since=2h catch-up)

Why pub/sub

Publisher and subscriber never talk directly, so no server to host, secure or keep awake.

Push, not poll

Updates arrive in about a second instead of refreshing on a timer.

Resilient

Auto-reconnect with replay of recent messages after a dropped connection.

Honest limits

The topic is secret but not authenticated, and everyone shares one channel. Production would use signed webhooks and per-user topics.

Status: the website side is built and tested. The chatbot's publishing block is the last piece to connect in the flow.
